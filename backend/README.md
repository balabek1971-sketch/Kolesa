# QazAuto API


## Cloudflare Stream

New videos use Cloudflare Stream when `CLOUDFLARE_STREAM_ACCOUNT_ID` and
`CLOUDFLARE_STREAM_API_TOKEN` are set. The browser receives a one-time direct
upload URL; the API token never reaches Vercel or the browser. Register
`POST /v1/hooks/cloudflare/stream` as the Stream webhook and store its signing
secret in `CLOUDFLARE_STREAM_WEBHOOK_SECRET`. Until Stream is configured, the
existing R2 video path remains available for previously deployed environments.
Go API for server-controlled marketplace operations. The browser must never receive the
Supabase `service_role` key, R2 secret keys, or webhook secrets.

## Local run

1. Install Go 1.23 or newer.
2. Copy `.env.example` values into your local environment.
3. Run `go test ./...`.
4. Run `go run ./cmd/api`.
5. Open `http://localhost:8080/healthz`.

Available routes:

- `GET /healthz` and `GET /readyz` for Railway health checks.
- `GET /v1/status` for public service metadata.
- `GET /v1/me` for a verified Supabase user. Send `Authorization: Bearer <access_token>`.
- `POST /v1/listings/{id}/media/photos/upload-url` creates a short-lived R2 upload.
- `POST /v1/listings/{id}/media/video/upload-url` creates a short-lived R2 upload.
- `POST /v1/listings/{id}/media/{mediaId}/complete` verifies and records an upload.
- `POST /v1/hooks/supabase/send-sms` for the signed Supabase Send SMS Hook.

The API verifies ES256 access tokens against the project's public JWKS and validates
issuer, audience, role, session, and expiry. Never put `SUPABASE_SERVICE_ROLE_KEY` in
Vercel or any `VITE_*` variable.

## Railway

Create a Railway service with `backend` as its root directory. Add secrets through Railway
Variables and deploy using the included `Dockerfile` and `railway.json`.

## Phone authentication with Mobizon

1. Add these Railway variables:
   - `SUPABASE_AUTH_HOOK_SECRET` - the complete secret generated by Supabase, including `v1,whsec_`.
   - `SMS_PROVIDER=mobizon`.
   - `MOBIZON_API_KEY` - the Mobizon API key. Never add it to GitHub or Vercel.
   - `MOBIZON_SENDER` - optional registered sender name. Leave empty to use Mobizon's available default.
2. Deploy the API and copy its public HTTPS domain.
3. In Supabase Dashboard open `Authentication > Hooks > Send SMS`.
4. Select an HTTP hook and set its URL to
   `https://YOUR-RAILWAY-DOMAIN/v1/hooks/supabase/send-sms`.
5. Copy the generated hook secret to the Railway variable from step 1 and redeploy.
6. Enable Phone authentication in Supabase.

Supabase creates the OTP. The API verifies the Standard Webhooks HMAC signature before
sending it to Mobizon. Only Kazakhstan E.164 numbers (`+7` plus 10 digits) are accepted.
The API key, phone number, and OTP are never written to application logs.

## Cloudflare media

Railway holds `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`,
`R2_PUBLIC_BUCKET`, and `R2_PUBLIC_BASE_URL`. The browser receives only short-lived
upload URLs.

Configure R2 bucket CORS for the production Vercel origin and `PUT` requests with the
`Content-Type` header. Add `VITE_API_BASE_URL` and `VITE_R2_PUBLIC_URL` to Vercel.
Photos upload with concurrency 3; video uploads after them. Railway never receives
the media bytes. The API verifies each object in R2 before marking it ready.
